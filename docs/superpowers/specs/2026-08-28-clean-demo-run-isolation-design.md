# 干净演示运行隔离设计

## 目标

每次运行 `start_frontend_demo.cmd` 时，前端只展示本轮实验产生的数据。历史实验数据库继续保存在 `cloud_edge_project/data/experiments`，不执行删除或清空。

## 当前问题

`start_project.ps1` 每次都会创建新的实验 ID 和独立的 Scheduler、Cloud、Summary 数据库，但上一次启动的三个宿主机服务可能仍占用 8003、8004、8006 端口。当前健康检查会把旧服务误认为本轮新服务已经启动，导致前端继续读取上一轮数据库。

## 设计

在启动新的宿主机服务前，对 8003、8004、8006 分别执行以下流程：

1. 若端口空闲，继续启动。
2. 若端口被占用，读取监听进程信息。
3. 只有进程命令行同时符合本项目路径、对应模块与端口时，才停止该旧进程。
4. 等待端口释放并再次验证；若仍被占用，终止启动并明确报告端口和占用进程，不误杀其他程序。
5. 使用本轮新生成的实验目录分别启动 Scheduler、Cloud、Summary。

8088 前端网关继续复用，因为它只代理固定服务端口；三个后端切换到本轮数据库后，页面刷新即可读取本轮数据。

Edge 容器继续使用现有流程：停止旧容器，通过本轮 `EXPERIMENT_ID` 启动并使用新的 Edge 数据库目录。

## 数据边界

- 保留：历史实验目录、模型文件、模型版本、配置、密钥、源代码。
- 隔离：本轮 Scheduler、Cloud、Summary 和 Edge 运行数据。
- 不执行：删除历史数据库、清空数据库表、删除 Docker 数据卷。

## 错误处理

- 非本项目进程占用服务端口：停止启动，提示用户关闭具体占用程序。
- 旧项目进程未能停止或端口未及时释放：停止启动，不继续进行健康检查。
- 新服务启动失败：现有健康门继续报告失败，不发送演示数据。

## 验证

1. 自动化测试验证端口归属识别：项目旧服务可停止，非项目进程不可停止。
2. 自动化测试验证启动顺序：端口清理发生在三个宿主机服务启动前。
3. PowerShell 语法解析通过。
4. 实际连续启动两次：第二次生成新的实验 ID，接口计数从 0 开始，旧实验目录仍然存在。

## 成功标准

- 第二次启动不读取第一次的设备、计数、处置和模型更新记录。
- 本轮发送前页面显示 0 条，本轮发送后只累加本轮数据。
- 历史实验文件不被删除。
- 不停止任何非本项目进程。
