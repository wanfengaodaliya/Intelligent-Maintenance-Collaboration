# V0.1 接口兼容实现设计

## 目标

在不破坏仓库现有轴承 `packet_id` 工作流的前提下，实现根目录《云边协同项目接口说明文档》V0.1 约定的 `task_id` 主流程、日志统计和冲突仲裁接口。

## 方案选择

采用请求结构分流的兼容适配方案。V0.1 请求具有 `task_id`、`task` 或 `decision_id` 等文档字段；现有轴承请求继续使用 `packet_id`、发送器字段或场景处理器字段。各 HTTP 入口只做结构识别，将请求交给对应的既有实现或 V0.1 实现，不修改轴承分析、模型更新和发送器协议。

相比直接替换现有契约，这一方案能保持现有 68 项测试与轴承业务可用；相比新增一套重复端口，它继续使用文档规定的统一接口和端口，便于现有调用方联调。

## 组件与数据流

1. `common/schemas.py` 增加 `TaskRequest`、`EdgeResult`、`ScheduleDecision`、`CloudResult`、`TaskLog` 所需的 V0.1 校验函数，错误继续使用现有 `ContractError` 结构。
2. 边缘和云端推理入口根据请求是否为 V0.1 结构分流，返回文档字段；原 `SensorPacket` 和轴承场景处理保持不变。
3. `/scheduler/decide` 在包含嵌套 `task`、`edge_result`、`network_state`、`node_state` 时调用既有规则调度器，其他发送器分配请求继续调用 `AssignmentScheduler`。
4. 日志服务同时接受 `TaskLog` 和旧 `TaskTrace`，统一从 JSONL 读取并计算文档指标；任务列表对两类记录分别输出其公开字段。
5. 新增独立 `consistency_service`，提供 `/consistency/resolve` 和 `/health`，并纳入 `start_all.py` 与 8005 端口配置。

## 行为与错误处理

- 必填字段缺失、类型错误、比例超出 0~1 或非法 `route` 均返回 HTTP 400 和机器可读错误码。
- V0.1 调度严格实现文档优先规则：云不可用时 `fallback_edge`；云可用且置信度低于 0.8 时 `cloud`；置信度不低于 0.8 时 `edge`。
- 仲裁按设备分组检测相反动作和功率超限；有相反动作时选择优先级最高、置信度次高的决策，并返回可解释原因。
- 配置文件提供端口，代码不写死服务端口或模型路径。

## 测试策略

使用真实 FastAPI 路由或公开函数完成测试驱动开发，先验证测试因缺少 V0.1 行为而失败，再实现最小代码。覆盖五类公共格式、边缘/调度/云端主链路、日志写入与指标、任务列表、仲裁和所有新增健康检查。最后运行仓库完整测试套件并执行本地直接演示。

## 范围边界

本次不实现 PER-DDPG 训练、真实模型部署、前端页面、雾节点执行器或能源优化算法；`fog` 和 `edge_cloud` 仅作为契约允许的路由值，不由第一版规则主动选择。
