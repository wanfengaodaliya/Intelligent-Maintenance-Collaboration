# 本机双边缘节点启动设计

**目标：** 让 `start_project.ps1` 在单台开发机上启动并注册 `edge_01` 与 `edge_02`，使调度器可将三个 Sender 的任务分发到两个节点。

## 范围

- 保留网络模拟器既有的两条边缘通道：
  - `edge_01`：服务 `8001`，出站代理 `18011`（Scheduler）和 `18021`（Cloud），调度回调代理 `18042`，MQTT 主题 `edge/edge_01/input`。
  - `edge_02`：服务 `8002`，出站代理 `18051`（Scheduler）和 `18053`（Cloud），调度回调代理 `18052`，MQTT 主题 `edge/edge_02/input`。
- Scheduler 的 `SCHEDULER_EDGE_NODES_JSON` 同时注册两个节点及各自的回调地址和主题。
- LLM 服务由 `8002` 改为 `8005`；两个 Edge 的 LLM 调用地址同时改为 `http://127.0.0.1:8005`。
- 两个 Edge 使用独立的可写运行状态：各自的 SQLite 数据库、路由错误日志、云复核缓存、原始样本目录和模型更新状态文件。H5 模型目录仍只读共享。
- 启动脚本分别检查两个 Edge 以及 LLM（未传 `-SkipLLM` 时）的健康状态。

## 不在本次范围内

- 不修改网络模拟器的链路、端口、MQTT Broker 或 Sender 配置。
- 不处理 Cloud 对诊断结果返回 HTTP 400 的独立接口契约问题。
- 不改变 H5 模型文件或模型版本。

## 成功标准

1. 运行启动脚本后，Scheduler 的健康接口显示两个已注册且在线的边缘节点。
2. `edge_01` 与 `edge_02` 分别在 `8001`、`8002` 返回本节点的健康信息，且 MQTT 已连接。
3. 未传 `-SkipLLM` 时，LLM 在 `8005` 可用，两个 Edge 的配置均指向 `8005`。
4. 双节点运行时不共享同一个 SQLite 数据库或其他可写运行目录。
