# 前端实时记录与轮次设备编号设计

## 目标

让总览、设备仲裁/决策、全局分析和调度拓扑展示真实且可解释的数据；同一条 Sender 命令的每轮三轴承使用递增设备编号，避免不同轮次都落到 `machine_01`。

## 已确认事实

- 总览初始出现的 20 个数据包来自浏览器 `localStorage` 中的旧流记录，并非后端启动后自动发送。
- Sender 配置目前只有一个固定 `device_id=machine_01`，`--rounds` 仅重复调用三 Sender，不改变设备编号。
- 当前 SQLite 中存在大量 `cloud_device_decision_result` 和 `global_analysis_result`；它们分别是设备级最终决策和周期全局分析。
- `device_arbitration_record` 当前为空。真正的设备仲裁只在设备结果存在冲突并调用云端仲裁后产生，不能用普通设备决策冒充。
- 网络链路接口已提供 `state_since_ns`、`applied_state_since_ns`、`last_apply_timestamp_ns` 等权威时间字段。

## 范围

### 1. 总览数据包统计

- 实时卡片只统计本次页面会话通过 SSE 收到的数据，页面首次打开从 0 开始。
- 浏览器旧缓存不再恢复到实时卡片和实时明细流中。
- 移除会污染真实演示数据的自动流缓存恢复逻辑；不改变后端 MQTT 或数据库数据。

### 2. Sender 轮次设备编号

- 配置中的 `device_id` 作为首轮编号，例如 `machine_01`。
- 同一条命令内，第 N 轮使用首轮数字后缀加 `N-1`，并保留原后缀宽度：`machine_01`、`machine_02`、……。
- 一轮内三个 Sender/轴承共享同一个设备编号。
- 每次新启动命令仍从配置编号开始；不引入跨进程永久计数文件。
- 配置编号没有数字后缀时，`--rounds 1` 仍可运行；多轮时给出明确错误，避免生成未经约定的名称。

### 3. 设备决策与仲裁浏览

- 云端新增只读“最近设备决策”接口，支持 `device_id` 可选筛选和有上限的 `limit`。
- 云端新增只读“最近设备仲裁”接口，支持 `device_id` 可选筛选和有上限的 `limit`。
- 返回顺序统一为最新在前，结果使用数据库保存的原始 JSON。
- 前端页面分成“最近设备决策”和“冲突仲裁记录”两个区域，按设备 ID 和记录时间自动显示；点击记录显示详情。
- 仲裁表为空时明确显示“暂无冲突仲裁记录”，保留按 `conflict_id` 精确查询能力，但不再要求用户必须手填才能看到页面内容。

### 4. 全局分析浏览

- 全局分析仓库和 API 新增跨设备最近结果列表，支持场景、设备 ID 和数量筛选。
- 页面加载后自动读取最近记录，并周期刷新。
- 列表显示设备 ID、分析时间、健康状态、趋势和任务数；点击记录复用现有详情渲染。
- “执行分析”和“读取指定设备最近结果”的现有能力保留。

### 5. 调度拓扑时间参考

- 链路状态优先按后端实际生效的 `applied_parameters.state` 和 `available` 判断，尚未应用时回退到 `current_state`；不再依赖接口不存在的 `status/toxics` 字段。
- 每条链路优先显示 `applied_state_since_ns` 对应的“状态开始时间”，尚未应用时回退到 `state_since_ns`。
- 链路板块显示本次成功获取数据的“刷新时间”。
- 时间转换统一处理纳秒 Unix 时间戳，缺失值显示 `-`。

## API 约定

- `GET /cloud/device-decision-results/recent?device_id=<optional>&limit=<1..200>`
- `GET /cloud/device-arbitration/recent?device_id=<optional>&limit=<1..200>`
- `GET /cloud/global-analysis/recent?scenario_type=bearing&subject_id=<optional>&limit=<1..200>`

成功响应统一为：

```json
{
  "success": true,
  "items": [],
  "count": 0
}
```

非法 `limit` 返回 HTTP 400 和稳定错误码；数据库不可用返回 HTTP 503。列表为空不是错误。

## 验证标准

1. 新开总览时数据包实时计数为 0，收到一组 80 包后显示 80，不再自动混入旧 20 包。
2. `--rounds 2` 的六个任务摘要中，前三个为 `machine_01`，后三个为 `machine_02`。
3. 设备页面无需输入 `conflict_id` 即可看到按时间倒序的真实设备决策；当前仲裁数据为空时显示准确空状态。
4. 全局分析页面可直接按设备和时间选择数据库已有结果。
5. 拓扑链路显示后端状态及状态开始时间，板块显示刷新时间。
6. 新增后端与 Sender 单元测试通过，前端静态结构检查和现有相关测试通过。

## 不在本次范围内

- 不人为制造冲突或仲裁数据。
- 不修改模型推理、MQTT 投递、Scheduler 路由或数据库既有记录。
- 不实现跨命令永久递增设备编号。
- 不重构无关页面或清理无关历史代码。
