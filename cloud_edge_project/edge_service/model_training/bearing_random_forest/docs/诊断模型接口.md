## 诊断模型输入

当前边缘诊断模型接收的不是原始波形，而是当前单包经过降采样和特征提取后的 `PerceptionResult`。

HTTP 接口：

```text
POST /infer
Content-Type: application/json
```

完整请求示例：

```json
{
  "request_id": "task-001:sender-01:packet-001:8d3f5e",
  "remaining_timeout_ms": 150.0,
  "input": {
    "device_id": "device-01",
    "bearing_id": "bearing-01",
    "task_id": "task-001",
    "packet_id": "packet-001",
    "sender_id": "sender-01",
    "sequence_number": 1,
    "end_generate_timestamp_ns": 1786410000000000000,
    "feature_generated_at_ns": 1786410000010000000,

    "perception_quality": {
      "status": "good",
      "flags": []
    },

    "features": {
      "vibration": {
        "source_sample_rate_hz": 64000,
        "analysis_sample_rate_hz": 16000,
        "rms": 0.35,
        "absolute_peak": 1.8,
        "kurtosis": 3.1,
        "dominant_frequency_hz": 120.0,
        "band_power_ratio_500_2000": 0.31,
        "spectral_entropy": 0.64,
        "unit": "mm/s"
      },

      "phase_current_1": {
        "source_sample_rate_hz": 64000,
        "analysis_sample_rate_hz": 16000,
        "rms_a": 2.4,

      },

      "phase_current_2": {
        "source_sample_rate_hz": 64000,
        "analysis_sample_rate_hz": 16000,
        "rms_a": 2.35,
        "absolute_peak_a": 3.38,
        "unit": "A"
      },

      "current_relationship": {
        "current_imbalance_ratio": 0.03
      },

      "operating_context": {
        "shaft_speed_rpm": {
          "mean": 900.0,
          "last": 900.0,
          "minimum": 899.5,
          "maximum": 900.5,
          "standard_deviation": 0.3
        },
        "load_torque_nm": {
          "mean": 0.7,
          "last": 0.7,
          "minimum": 0.69,
          "maximum": 0.71,
          "standard_deviation": 0.01
        },

          "mean": 1000.0,

```

这里的 `operating_context` 是当前数据包自带的转速、负载、温度等工况特征，不是相邻数据包上下文。

### 输入字段约束

- `sequence_number`：任务流程中为 `1～80`
- 原始采样率：当前固定为 `64000 Hz`
- 分析采样率：当前固定为 `16000 Hz`
- `dominant_frequency_hz`：`20～8000`
- 功率占比、频谱熵：`0～1`
- 所有数值必须为有限数，不能是 `NaN` 或无穷大
- `perception_quality.status`：

```text
good
warning
```

允许的质量标记：

```text
DEVICE_NOT_RUNNING
VIBRATION_CONSTANT_SIGNAL
PHASE_CURRENT_1_CONSTANT_SIGNAL
PHASE_CURRENT_2_CONSTANT_SIGNAL
```

目前代码定义的输入契约版本是：

```text
edge-model-input/1.1
```

但该版本号尚未真正放进请求 JSON，后续建议增加 `schema_version` 字段。

## 诊断模型输出

成功响应：

```json
{
  "valid": true,
  "request_id": "task-001:sender-01:packet-001:8d3f5e",
  "edge_result": "warning",
  "edge_risk_level": "medium",
  "confidence": 0.87,
  "model_version": "bearing-ml-v1.0.0",
  "latency_ms": 18.6
}
```

必需的业务输出字段是：

```json
{
  "edge_result": "normal | warning | fault",
  "edge_risk_level": "low | medium | high",
  "confidence": 0.0,
  "model_version": "非空模型版本号"
}
```

当前离线随机森林采用故障二分类：

```text
healthy -> normal
outer_ring_damage | inner_ring_damage -> fault
```

因此当前模型只输出 `normal` 或 `fault`，不负责区分内圈/外圈，也不产生 `warning`。
如果后续需要 `warning`，应在开发集上验证并冻结独立阈值，不能临时把未校准的随机森林概率
区间直接解释为预警。

约束：

- `confidence` 必须在 `0～1`
- 不能是 `null`
- 不能是布尔值
- 不能是 `NaN` 或无穷大
- 如果请求包含 `request_id`，响应必须原样返回同一个值

模型不需要输出：

- `data_quality_score`
- `action_grade`
- `recommended_action`
- `decision_source`

这些由模型外部的边缘流程计算。

### `data_quality_score`

它根据当前包的感知质量标志计算：

- 无质量异常：`1.0`
- `DEVICE_NOT_RUNNING`：扣 `0.2`
- 其他质量标志：每项扣 `0.1`
- 最低为 `0.0`

### `action_grade`

由 `edge_result + edge_risk_level`转换：

| 诊断结果 | low | medium | high |
|---|---:|---:|---:|
| normal | 0 | 1 | 2 |
| warning | 1 | 2 | 3 |
| fault | 2 | 3 | 4 |

动作对应关系：

```text
0 = continue_operation
1 = enhanced_monitoring
2 = scheduled_inspection
3 = urgent_intervention
4 = shutdown
```

## 模型失败响应

```json
{
  "valid": false,
  "request_id": "task-001:sender-01:packet-001:8d3f5e",
  "error": "MODEL_INFERENCE_FAILED",
  "detail": "optional error detail",
  "latency_ms": 18.6
}
```

支持的错误码包括：

```text
MODEL_BUSY
MODEL_UNAVAILABLE
MODEL_INPUT_INVALID
MODEL_INFERENCE_FAILED
MODEL_INFERENCE_TIMEOUT
MODEL_OUTPUT_INVALID
```

边缘收到失败或超时后会进入代码降级路径。

## 云端诊断模型的建议

包级云复核收到的是当前包的 `raw_packet`。真实实现时建议采用：

```text
当前高采样率原始包
→ 云端重新预处理和提取特征
→ 生成同样的 input.features
→ 调用同一套诊断模型输出契约
```

这样边缘模型和云端模型可以共享输入/输出结构，区别只在模型规模、特征精度和计算资源，不需要维护两套完全不同的诊断结果格式。当前云端这一部分仍是确定性 mock，需要后续替换。
